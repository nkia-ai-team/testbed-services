# F02-H 캐시 무력화 재설계 초안 (2026-08-06)

> 상태: **설계 초안 — 사다리 실측 전** (실측은 41종 재시도 배치 완주 후).
> 결정 경위: 0804 findings #24에서 인과 부재 실측 확정(disk 81% / order p95 41.9ms),
> 권고는 파킹이었으나 사용자 결정(08-06)으로 **선택지 (2) 캐시 무력화 재설계**를 택했다.

## 왜 기존 F02-H는 인과가 없었나

디스크를 81%까지 태워도 업무 질의가 느려지지 않은 이유는 **핫 워킹셋이 캐시 안에 살기
때문**이다. 업무 질의는 최근 행만 만지고, 그 페이지는 shared_buffers·OS 페이지 캐시에
상주한다. 디스크가 아무리 바빠도 캐시 히트에는 IO가 없다.

## 성립 조건 실측 (08-06, 읽기 전용)

| 항목 | 값 |
|---|---|
| shared_buffers | **128MB** |
| PG 파드 메모리 limit | **512Mi** (OS 페이지 캐시 상한도 이 안) |
| commerce DB 크기 | **4,272MB** — 캐시 총량의 ~8배 |
| 최대 테이블 | shipping_schema.outbox_events 861MB · payment_schema.payment_logs 610MB · inventory_schema.outbox_events 537MB |

데이터가 캐시의 8배라 **shared_buffers 축소(재기동 필요) 없이** 캐시 밖 대역을 도는
질의만으로 캐시를 밀어낼 수 있다. 재기동 없는 설계가 가능하다는 것이 핵심 — F18-P
계보(재기동은 자백이자 자기 실격)와 같은 이유로 PG 재설정 경로는 쓰지 않는다.

## 재설계된 인과 사슬

```
io 사다리(기존 io-20000 레버, disk_io_util ~80%)          … 장치를 바쁘게
+ 캐시 무력화 companion(payment_logs 등 대형 테이블
  넓은 대역 스캔 질의를 주기 실행)                          … 캐시를 밀어냄
→ 업무 질의가 콜드 페이지를 "바쁜 장치"에서 읽게 됨
→ order/payment p95 상승 (slow-not-failed)
```

두 레버가 **함께** 있어야 성립한다: 스캔만 있으면 장치가 한가해 콜드 읽기도 빠르고,
IO만 있으면 (기존 실측대로) 캐시가 흡수한다.

## 주입 표면

- io 사다리: 기존 `host.stress`/io 프로파일 재사용 (0804 #24 실측 도구와 동일 경로).
- 캐시 무력화 질의: `db.workload` 프로파일(기존 존재) 확장 검토.
  - 질의 형태: `SELECT count(*), sum(...)  FROM payment_schema.payment_logs WHERE <넓은 시간대역>`
    류의 seq-scan 유도. **업무 테이블 잠금·쓰기 금지**, 읽기 전용.
  - G6 자백 주의: 스캔 질의가 DPM/pg_stat에 찍히는 것은 "배치성 리포트 질의"로
    자연화 가능한지 검토 필요 (L2 주입 자연화 미결과 같은 갈래).

## 성공/감별 조건 방향 (사다리 실측 후 확정)

- success: order_p95 (or payment_p95) 유의 상승 + disk_io_util 고수준 + entry 2xx 유지
- must_rule_out: 오류율 급등(그건 다른 정체성), PG 커넥션 고갈, 캐시 스캔 질의 자체가
  성공조건 신호가 되는 것(#15 교훈의 캐시판 — 스캔 질의의 응답시간을 재지 말 것)
- 회복: 스캔 중지 + (필요시) 대형 테이블 1회 워밍 or 자연 회복 대기 — 캐시 재적재
  시간이 회복 지연으로 보일 수 있음을 판정 창에 반영

## 사다리 실측 계획 (배치 완주 후)

1. 평시 기준선: order/payment p95, disk_io_util, PG buffer hit ratio (`pg_stat_database.blks_hit/blks_read`)
2. 스캔 단독 사다리: 주기(10s/5s/2s) × 대역(1/4, 1/2, 전체 테이블) — hit ratio 하락과 p95 반응 확인
3. io 단독(기존 실측 재사용: 81%에서 무반응) 대조 유지
4. 복합: 스캔×io 격자에서 p95가 유의하게 움직이는 최소 조합 → approved-fixed 레벨로 고정
5. 임계는 실측 분포(p95 평시 대비 배수)로 — 게이트 수치를 가정으로 두지 않는다(0804 #29 교훈)
