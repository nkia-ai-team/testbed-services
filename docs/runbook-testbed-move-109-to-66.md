# 테스트베드 이전 작업 계획 (109 → 66)

## 0. 한눈에 보는 결론

| 질문 | 답 (해야 할 일) |
|---|---|
| 왜 옮기나 | 109(GB10)를 팀이 새 LLM 시험에 쓴다. 테스트베드는 66(bon04-13, Proxmox VE 9.2)으로 간다 (2026-10-15 결정) |
| 언제까지 | 기한 없음. 확인할 것을 다 확인하고 넘어간다. 109 는 전환이 끝난 뒤 반납한다 |
| 그대로 옮길 수 있나 | **없다.** 109 는 ARM(aarch64), 66 은 x86(Xeon Silver 4214R × 2). VM 디스크, 앱 이미지 19종, 결함 이미지 25종, 에이전트, 러너 이미지를 x86 으로 새로 만든다 |
| 녹화는 멈추나 | 66 을 119 에 연결하기 전까지(1, 2단계와 4단계 준비)는 109 에서 계속 녹화한다. 66 의 앱은 109 앱과 서비스 이름, 대상 번호가 같아서 둘이 동시에 119 로 보내면 녹화가 섞인다. 그래서 3단계(119 연결) 직전에 109 녹화를 멈추고 109 VM 을 끈 뒤, 3~5단계 동안(기준선 쌓기 포함 며칠) 녹화를 쉰다 (2026-10-15 결정) |
| 전환 조건 | §2 기준표의 데이터 종류가 66 에서 **모두** 119 에 들어오고, 시험 녹화 덤프가 109 덤프와 같은 구성일 때만 넘어간다. 하나라도 비면 넘어가지 않는다 |
| 부하 강도는 그대로인가 | 메모리 한도로 터지는 시나리오는 거의 그대로다. CPU 포화, 디스크 IO(fio), stress-ng 계열은 x86 과 SATA SSD 에서 다시 재야 한다 (§4 5단계) |
| 접속 정보 | 66 관리자 계정은 컨플루언스 "bon04-13(192.168.200.66) Proxmox VE 가상화 호스트 구축 및 접속 정보" 문서를 본다. 이 문서와 저장소에는 비밀값을 적지 않는다 |

## 1. 두 서버 비교

| 항목 | 계획 | 이유 |

## 4. 단계

각 단계는 앞 단계의 확인 칸이 다 채워져야 시작한다. 순서는 1 → 2 → 4(119 와 무관한 준비) → 109 정지 → 3 → 4 나머지 → 5 → 6 이다. 109 녹화는 109 정지 전까지 그대로 돈다.

**66 을 119 에 연결하기 전 지킬 것**: 66 의 앱 OTel 주소는 tb-ops(192.168.122.20:14318)로만 두고 109 중계기나 119 를 넣지 않는다. SMS, KCM, syslog, 119 등록도 109 정지 뒤에 한다.

9. **APM 을 가린 평가 조건**: 7번의 목적은 녹화만으로는 검증되지 않는다(녹화본에는 APM 데이터도 함께 담긴다). 서버 자원 시나리오(F80-R 부터)를 APM 데이터(trace, APM 지표)를 뺀 조건으로도 평가해 달라고 연구원에게 요청한다. 어떤 케이스가 그 대상인지 meta.json 에 표시할지는 그때 정한다.
10. **원장 대사 거짓 불일치 고치기(2026-10-23 사용자 결정)**: core-banking-ledger 의 `LedgerService.sumImbalance()` 가 출금 합계와 입금 합계를 SQL 두 문장으로 따로 구한다. Oracle 은 문장마다 읽는 시점이 달라서, 두 문장 사이(원장 표가 커져 약 3.5초)에 들어온 이체가 입금 합계에만 잡히고 실제 장부는 맞는데 `Ledger reconciliation MISMATCH` 경고와 "원장 불일치" 인시던트가 난다(차이는 늘 음수, 이체 몇 건 크기, 아침 부하가 오르면 매 회차). MariaDB 시절에는 트랜잭션 안의 두 문장이 같은 스냅숏을 봐서 없던 현상으로, Oracle 전환(a140ee5)의 부작용으로 본다. 설계 의도(코드 주석 "항상 0 이어야 한다", F14 설계 시트의 "imbalance 는 영원히 0")와도 어긋난다. 두 합계를 한 문장(`sum(case when direction='DEBIT' ...) - sum(case when direction='CREDIT' ...)`)으로 구하도록 고치고, 진짜 불일치(한쪽 줄만 남음)는 그대로 잡히는지 시험한다. v3 녹화본 대부분에 이 배경 경고가 깔려 있어 v3 도중에는 고치지 않는다. 배경 잡음이 필요하면 거짓 결함이 아니라 설계된 무관 사건(4번의 미끼 배포처럼)으로 넣는다.
